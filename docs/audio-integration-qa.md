## データ

- 送信済み音声ZIPと生成元の台本を取得し、全文・ID・話者・順序を比較して一致。
- 1,164 MP3（190 / 336 / 638）、24kHz・mono、32,496,480 bytes、5,416.080秒。最短0.624秒、最長56.064秒。
- 全件ZIP CRC・ffprobe・ffmpeg完全デコード・RMSを実行。欠落0、破損/デコード失敗0、無音0。最低RMS -35.3dBFS。同一音声4件は同一本文のみ。
- `audio-manifest.json` と1,164個のファイルを `scripts/validate-audio.mjs` がID・話者・本文・順序・ファイルサイズ・SHA-256まで再照合。ビルドでも必須実行。
- 全件の聴取・音声認識による語句の照合は未実施。生成物の発音や抑揚を全件保証しない。

## 自動検査

Nodeの単体/回帰テストと構文/静的ビルドを実行。検査内容は既存台本・辞書・解説の全件対応、役と記録の保持、遅延音声の取り消し、連続順序、自分の番での停止、模範音声、途中再開、速度/シーク、範囲反復、発話時間の自動進行と中断、欠落/再生制限、上限付き音声cache、Rangeとオフライン再生。

Browser interaction QAのCIに `tests/audio-browser-qa.mjs` を追加。実行結果はCIの完了後に記録する。コードが存在することを実行済みとは扱わない。

## クラウドChromeで実操作・計測した項目

- 提供MP3の再生・一時停止・再開、再生秒数の更新、終了、前後セリフに対応する文章詳細。
- 共通シートを介した1.25×速度選択と、元の文章詳細・停止位置の維持。
- MOLLIEとして範囲3〜6を音声練習。GILESの3番目の実音声の後、4番目のMOLLIEで停止し正解は非表示。
- 練習→文章詳細→bruteの辞書→文章詳細→練習で、2/4・MOLLIE・非表示状態を維持。再読み込み後の「続き」も2/4に復元。
- 練習シート内の役選択をGILES→MOLLIEで実操作。modalの背面に隠れたメニューを、dialog所有のpopoverに修正して再検査。
- 320 / 390 / 768 / 1280 CSS pxのiframeで文書幅とシート幅を計測。文書幅は各表示幅と一致し、シート内の横はみ出し0。320px時の主要操作の右端は286px、下端は728.2pxで表示内。
- 390pxおよびPC幅の台本・練習シートを視覚確認。全幅の行、薄い仕切り、単語の下線、半透明円のスティックを維持。

クラウドのCSS寸法・ブラウザー操作であり、Android実機の検査ではない。観測ログにはブラウザー拡張のmetadata送信エラーがあり、アプリ由来の例外とは区別する。

## UIと状態の変更

練習は以前の独立ページから、台本を基点とする共通ボトムシートへ変更した。既存の穴埋め・音声練習、範囲、役、学習/要復習、前へ・次へ・正解表示・続きの保存を維持。台本のセリフ本文・解説・辞書・進捗・栞・メモのデータは変更しない。開閉で台本DOMを作り直さず、閲覧位置を維持する。自分の答えを隠す設定は背面の自役本文にも適用する。
